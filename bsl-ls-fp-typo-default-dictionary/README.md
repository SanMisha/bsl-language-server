# Typo: встроенный словарь исключений при настройках по умолчанию

У диагностики `Typo` есть встроенный словарь исключений — ключ `diagnosticExceptions` в `TypoDiagnostic_ru.properties` и `TypoDiagnostic_en.properties`. Если у `Typo` в настройках нет объекта параметров, словарь не применяется, и слова из него помечаются опечатками. Здесь минимальный пример и скрипт, который это показывает.

## Что внутри

- `src/Модуль.bsl` — один модуль. Три слова из встроенного словаря стоят в разных местах, которые проверяет `Typo`:
  - `Субконто` — в имени процедуры `ПриИзмененииСубконто`;
  - `Модифицированность` — слева от присваивания;
  - `Возр` — в строковом литерале.

  Строка 6 — контрольная: `"Атмена"` с настоящей опечаткой, замечание по ней верное в обоих прогонах.
- `cfg/default.json` — `{"language": "ru"}`, параметров `Typo` нет. Так же ведёт себя `"Typo": true`.
- `cfg/with-params.json` — `{"Typo": {"minWordLength": 3}}`. Это значение по умолчанию, только заданное явно.
- `run.sh` — запускает `analyze` с каждым файлом настроек и печатает замечания `Typo`.

## Запуск

Нужны Java 21+, jq и bash (Linux или macOS).

    ./run.sh <путь к bsl-language-server-1.1.0-rc.9-exec.jar>

Отчёты и логи — в `out/default/` и `out/with-params/`. Без bash:

    java -jar <путь к jar> analyze --srcDir src --configuration cfg/default.json --outputDir out/default --reporter json
    java -jar <путь к jar> analyze --srcDir src --configuration cfg/with-params.json --outputDir out/with-params --reporter json

## Что ожидается

В обоих прогонах одно замечание — строка 6, `"Атмена"`.

## Что получается на 1.1.0-rc.9

    == cfg/default.json — параметров Typo нет
    замечаний Typo: 4
      строка 1: Возможная опечатка в "Субконто"
      строка 3: Возможная опечатка в "Модифицированность"
      строка 4: Возможная опечатка в "Возр"
      строка 6: Возможная опечатка в "Атмена"
    == cfg/with-params.json — Typo: {"minWordLength": 3}
    замечаний Typo: 1
      строка 6: Возможная опечатка в "Атмена"

Проверено на macOS 26.3.1 (Apple Silicon), OpenJDK 21.0.11. Тот же результат дают 0.25.0-ra.12, 0.29.0, 1.0.0, 1.0.7, 1.1.0-rc.4, rc.7 и rc.8. На 0.25.0-ra.11 в обоих прогонах одно замечание.
